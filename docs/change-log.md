## 2026-09-01：动作执行前按配置切换配装组

- 需求：废弃回家、师父和潜能挂机前扫描装备属性并计算“最优套装”的旧算法；改为由用户从原生配装 1/2/3 中明确选择。每个内置动作独立配置，并允许对动作栏中的每条按钮命令单独设置“先换装再执行”。
- 修改：删除插件设置中的“传送前智能换装”总开关，新增按角色隔离的“动作前配装”配置页。动作栏按钮按命令登记并可选“不换装/配装1/2/3”；执行时发送 `eqgroup 0/1/2`，等待 `dialog=pack` 的 `eq_group` 确认后只重放一次原动作，1.5 秒无确认时降级继续。底层仍支持内置动作规则，后续界面调整为只呈现当前动作栏按钮。
- 差异与清理：`prepareSmartEquipment`、`preparePotentialWorkEquipment` 及属性详情缓存不再被传送和挂机链调用；旧 `smartEquipmentOnTravel` 开关不再渲染或参与判断。潜能挂机仍选择收益最高活动，但工具装备不再自行扫描，改由用户为“智能挂机”指定完整配装组。

## 2026-09-01：出招设置改用扩展串行队列

- 现象：实测配置“无招 → 破气 → 踏歌行 → 五神赋”后，实际稳定变成“无招 → 踏歌行 → 破气 → 五神赋”。
- 差异与根因：插件设置页把排序结果写入游戏原生 `auto_pfm`。参考服务端 `WORLD.auto_pfm` 会在开战时用同步循环连续执行全部 `perform`，并不等待每招的释放时间；无招先建立释放状态后，紧随其后的破气被拒绝，随后扩展自动施法先选到踏歌行，形成稳定重排。此前增加的等待只作用于扩展定时器，无法约束服务端已经连续发出的原生队列。
- 修改：排序结果改为保存到按角色隔离的扩展首轮队列；保存时发送 `setting auto_pfm none` 关闭服务端原生连续队列，防止两套调度竞争。首次打开新页面时仍可读取旧原生顺序用于迁移。设置说明同步明确为“每场战斗逐招执行，完成后恢复冷却优先自动出招”。
- 验证：新增“无招 → 破气 → 踏歌行 → 五神赋”四招顺序回归检查，并保留逐招释放等待测试；完整扩展验证及上游无头浏览器烟测通过。仍需使用现网同一组合复测技能表现。

## 2026-09-01：自动出招顺序等待上一招释放完成

- 现象：配置出招顺序后，自动攻击可能在上一招的服务端 `gcd/busy` 状态尚未返回时继续发送下一招；非零出招时间的角色因此会出现部分技能越序、未成功施放，旧首轮队列也没有真正接入当前加载的自动施法循环。
- 差异与根因：拆分备份模块已经把智能施法的零秒判断改为“非零时间只发一招”，但页面实际加载的 `features/upstream-automation.js` 仍保留了相反判断；`auto-first-round.js` 只实现了队列消费函数，实际的智能/普通自动施法定时器均未调用它。队列发送后也仅依赖稍后到达的协议状态，没有本地释放时间闸门。
- 修改：实际加载的两条自动施法循环现先消费首轮队列；首轮每发出一招后按角色 `score2.releasetime` 等待，最低保留 350ms 协议反馈窗口，并继续服从服务端 `gcd` 与自身 `busy/faint` 状态。上游智能施法同步修正零秒解析，兼容小数、空格和颜色标签；非零出招时间每轮只发送一招，等待释放完成后才继续扫描。
- 验证：新增回归检查确认 1.2 秒释放时间下连续轮询不会发送第二招、时间到后才按序继续，并确认实际加载的上游代码已接入首轮队列及非零释放判断；完整扩展验证通过。Python Playwright 无头 Chromium 进一步确认 0.4 秒释放窗口内只发送第一招，等待后才按配置发送第二招。仍需登录现网，以至少两招且非零出招时间的角色完成实战验证。

## 2026-08-19：详情悬浮窗误触发隔离

- 现象：在师父技能界面点击“学习”等非详情操作时，偶尔自动打开自己的技能详情悬浮窗；快速切换对话框后也可能出现旧详情窗。
- 根因：技能详情响应只按技能 ID 匹配，没有区分 `skills` 与 `master` 来源；详情请求在同一界面执行其他命令时仍保留，隐藏界面的旧请求也可能继续消费响应。
- 修改：详情请求记录期望对话框来源；自己的技能只接受 `dialog=skills`，师父技能只接受 `dialog=master`；同一界面执行非详情命令时取消该界面的待处理详情请求；响应到达时清理已隐藏或脱离 DOM 的来源请求。
- 验证：新增自身/师父同技能 ID 的响应隔离回归断言，完整扩展验证通过。
- 补充：切换原生对话框或关闭对话框时清空详情等待队列，避免旧界面请求在延迟响应后重新打开悬浮窗。
- 补充：所有非详情命令（包括使用突破丹）统一清空全局详情等待队列，避免插件或原生按钮不属于标准对话框时仍触发旧技能悬浮窗。
- 修正：突破丹实际走 `_confirm` 前缀命令，上一版清理位于普通命令分支而未覆盖；现将详情请求清理前置到 `ContainerCommand` 分派入口，仅真正详情命令保留等待。
