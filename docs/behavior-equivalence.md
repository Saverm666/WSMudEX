# 行为等价性说明

## 保持不变的边界

- 扩展匹配 `wsmud2.com`、`wsmud2.cn`、`wxmud1.com` 及其子域名的 HTTP/HTTPS 页面。`wsmud2.com` / `wsmud2.cn` 仍替换原站客户端；`wxmud1.com` 保留原站 SPA，只叠加插件。
- 权限仍为 `scripting` 和 `storage`。
- `extensionEnabled` 存储键及 `updateExtensionStatus`、`GM_export`、`GM_import`、`GM_listKeys`、`GM_deleteKey` 消息名不变。新增扩展存储键 `wsmudSyncedPageSettings`，只用于跨站点回填页面 `localStorage`。
- 原站脚本拦截条件、停止观察的时机、逐个脚本加载规则、加载失败后继续执行的规则不变。
- localStorage 导入时仍对每个值执行 `JSON.stringify`；导出时仍优先 `JSON.parse`。
- 自动化脚本中的命令字符串、选择器、定时器、配置键和公开全局 API 未作人工改写。
- 两份大型脚本的运行产物仍是原来的单文件和单作用域；`sources/` 仅按连续语义边界保存源码片段，构建过程只执行原样拼接。
- 新增登录后自动执行一次官方 `sx greet` 命令，用于向本门派首席弟子完成每日请安；不发送聊天消息、不新增权限或联网目标，是否获得奖励及失败提示仍由游戏服务端判断。

## 转换方法

普通脚本仅做解析器驱动的格式化。三个扩展入口在保留分支与副作用顺序的前提下重命名了局部符号。重度混淆的游戏客户端通过静态 AST 转换解析字符串数组、解码包装器、死代码和混淆控制流，再统一格式化。

跨文件公开符号没有批量改名。它们虽然有些仍带历史命名风格，但其他脚本可能直接访问，强行重命名会破坏功能；可读版以行为不变为更高优先级。

## 原代码保留的联网目标

代码仍包含原作者加入的版本服务、文档/资源 CDN，以及 PushPlus、Bark、Server 酱、Qmsg、飞书机器人等可选推送地址。按使用者要求，登录时请求 `wsmud.ii74.com/hello/<角色>` 并显示节日祝福/远程公告的行为已移除；Raid 版本/节日公告也不再于登录时自动请求和弹出，只保留点击版本按钮后的手动查看。其余请求是否实际发生取决于原有功能和配置。

## 验证范围

`tools/verify-extension.mjs` 会检查全部 JavaScript 的语法、Manifest 引用、资源存在性、固定注入顺序、核心消息协议、存储键、语义片段与运行文件逐字一致性，以及旧随机文件名是否仍被入口引用。静态验证不能证明所有游戏服务器状态下的运行行为；首次实机使用建议保留原目录以便逐项对照。
